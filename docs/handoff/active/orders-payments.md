# JZL CLOSET 주문·결제·회원

적용 범위: 주문·KSNET·회원/비회원 동작 변경 또는 검수
이 문서는 현재 업무 지시가 아닌 활성 작업 규칙이다. 해당 작업의 현재 승인 범위를 확인한 뒤 필요한 절만 읽는다. 시작 시 일괄 로드하지 않는다. 날짜가 있는 실측·설정·예시는 그 날짜의 근거이며 지금 상태는 재확인한다.

## 주문 방식

카드·간편결제(KSNET)와 무통장입금 두 가지로 받습니다. 회원가입은 강제하지 않습니다.

```
무통장입금
  손님   장바구니 → 주문서 작성 → 주문번호 발급 → 계좌 입금
  사장님 텔레그램 알림 → 입금 확인(결제완료) → 공급처에 발송 요청 →
         송장 일괄등록(자동 배송중) → 배송완료

카드 · 카카오페이 · 네이버페이 (4-A)
  손님   장바구니 → 주문서 작성 → 주문 저장(결제대기) → KSNET 결제창 →
         카드 입력 → 결제 완료 화면
  서버   결제창이 돌려준 결제 Key 로 KSNET 에 직접 승인 확인 →
         금액·주문번호 대조 → 결제완료로 변경 → 텔레그램 알림
  사장님 결제 완료 알림 → 공급처에 발송 요청 → (이하 동일)
```

텔레그램 알림에는 받는분·연락처·주소·배송메모·상품 목록이 들어 있어
**그대로 복사해 공급처에 넘길 수 있습니다.** (서식 없는 평문으로 보냅니다)

공급처가 회신한 송장은 관리자 > 주문 관리 > **송장 일괄등록**에 붙여넣으면
주문번호로 매칭해 한 번에 저장하고 상태를 배송중으로 바꿉니다.
택배사 이름은 `CJ` · `CJ대한통운` · `대한통운` 처럼 적어도 알아봅니다.

- 주문 조회는 `/order-lookup` 에서 **주문번호 + 연락처** 로만 열립니다. (같은 IP 분당 10회 제한)
- 금액은 서버에서 다시 계산합니다. 클라이언트가 보낸 가격은 쓰지 않습니다.
- 주문이 생기면 옵션 재고가 줄고, 취소·반품하면 되돌아갑니다. (재고 미관리 조합은 건드리지 않습니다)
- 결제 수단은 `lib/payments/` 에 하나씩 들어 있습니다.
  (`bank-transfer.ts` 무통장입금 · `ksnet.ts` + `ksnet/` 카드결제)

### 카드결제 (KSNET) — 꼭 알아야 할 것

**돈이 오가는 경로입니다. 아래 네 가지는 절대 건드리지 마세요.**

1. **승인 확인은 반드시 서버가 합니다.** 결제창이 "성공" 이라고 말한 것은 근거가
   아닙니다. 손님 브라우저를 거쳐 오는 값이라 조작될 수 있습니다.
   `lib/payments/ksnet/approve.ts` 가 KSNET 서버에 직접 물어봅니다.
2. **금액은 항상 DB 에서 다시 읽습니다.** 승인 확인에 넣는 금액도, 돌아온 금액과
   맞춰 보는 금액도 전부 `orders.total_amount` 입니다.
3. **금액이나 주문번호가 어긋나면 결제완료로 바꾸지 않습니다.** `검토필요` 로 두고
   텔레그램으로 알립니다. 사람이 KSNET 거래내역과 대조해야 합니다.
4. **승인 확인에 실패해도 "결제실패" 라고 하지 않습니다.** 승인은 났는데 우리만
   모르는 상황일 수 있습니다. `승인확인실패` 로 두고, 손님에게는 "결제 확인 중"
   으로만 안내합니다. 여기서 재결제를 안내하면 이중결제가 납니다.

**취소는 관리자에서 직접 되지 않습니다.** KSNET 이 가맹점에 취소 API 권한을 주지
않습니다. 관리자 주문 상세에서 `[취소 요청 접수]` 를 누르면 상태가 `취소요청` 이
되고, 화면에 KSNET 거래번호(`trno`)와 승인번호가 크게 나옵니다. 그 번호로 대행사에
연락해 처리하고, 환불이 실제로 끝나면 `[취소 완료]` 를 누릅니다. 그때 재고와
사용 포인트가 되돌아갑니다.

**현금영수증은 PG 가 발급해 주지 않습니다.** 무통장입금 주문에서만 신청을 받아
두고, 운영자가 홈택스에서 직접 발급합니다. 관리자 주문 목록의
`현금영수증 미발급` 필터로 처리할 건을 모아 볼 수 있습니다.

**카드 주문은 자동취소하지 않습니다.** 무통장입금만 입금 기한이 지나면 자동
취소됩니다. 카드 주문을 자동으로 취소하면, 결제는 됐는데 우리가 승인 결과를 못
받은 건까지 지워져 가장 풀기 어려운 분쟁이 됩니다.

**환경변수** — `KSNET_MID` · `KSNET_MODE`. 넣지 않으면 테스트 상점아이디로
동작합니다. 운영으로 바꾸는 방법은 `.env.local.example` 에 적어 두었습니다.
KSNET 과 주고받은 원문은 전부 `payment_logs` 표에 남습니다. **지우지 마세요.**
분쟁이 났을 때 이 표가 유일한 근거입니다.

## 회원과 비회원

**회원가입을 강제하지 않습니다.** 비회원 주문이 그대로 남아 있고, 회원가입은 편의 기능입니다.

| | 비회원 | 회원 |
|---|---|---|
| 주문 | O | O (주문서 자동 입력) |
| 주문 조회 | `/order-lookup` 주문번호 + 연락처 | 마이페이지 > 주문 내역 |
| 1:1 문의 | O (조회용 비밀번호 필요) | O (마이페이지에서 확인) |
| 문의 조회 | `/inquiry/lookup` 문의번호 + 비밀번호 | 마이페이지 > 문의 내역 |

가입 전에 비회원으로 주문했다면 마이페이지 > 주문 내역의 **비회원 주문 불러오기**로
주문번호 + 연락처를 넣어 계정에 가져올 수 있습니다.
(이미 다른 계정에 연결된 주문은 가져올 수 없습니다)

탈퇴하면 프로필의 개인정보만 지우고 **주문 내역은 남깁니다.**
전자상거래법상 거래기록은 5년 보관 의무가 있습니다.
