# JZL_CLOSET 인수인계 H1

## 시작과 읽기 예산

- 로컬 저장소는 `johnlee79/jzl-closet`. `.handoff/profile.json`의 프로젝트·저장소·현재 정본만 사용한다. 관련 저장소와 이름이 비슷하다는 이유로 전환하지 않는다.
- 새 세션은 `00_START_HERE.md`와 지정된 현재 정본, 필요한 역할 안내만 읽는다. 전체 시작 문서·과거 대화·전체 댓글·보고·아카이브를 한꺼번에 읽지 않는다.
- 진입 문서는 파일당 2,600자, 등록 진입 문서 합계 8,000자, 최대 5개. 이 한도는 저장소 정책이며 ChatGPT 제품의 토큰 한도가 아니다.
- 현재 Issue는 본문만 먼저 확인한다. 근거가 필요한 경우 현재 정본이 지정한 댓글 ID만 좁게 읽는다. 댓글 목록 전체 조회, 댓글 페이지 자동 순회, 댓글 수 증가를 최신 승인으로 해석하지 않는다.
- 현재 파일/Issue가 없거나 모순되면 `UNKNOWN`을 유지하고 승인된 작업을 특정한다. 날짜·마지막 댓글·옛 NEXT를 현재 지시로 만들지 않는다.

## 누적 방지와 보존

- 상태 변경은 현재 행을 교체한다. 긴 과거 상태·로그·전체 대화는 추가하지 않는다. 완료 증거, 승인 범위, 남은 미확인, 다음 한 행동의 구분을 유지한다.
- 상세 규칙은 해당 작업에 필요한 활성 참조 문서의 절만 읽는다. 보관 원문은 감사·복구용이며 시작 입력이나 자동 활성 지시가 아니다.
- 현재 작업 범위를 넘는 쓰기·배포·DB·비밀·과금·공개·삭제 승인은 이 정책에서 생성되지 않는다. 이미 승인된 작업의 조건과 보안 규칙을 유지한다.
- `python3 tools/check_handoff.py --root . --static`로 프로필·정체·크기·아카이브 무결성을 확인한다. 외부 Issue 상태는 별도 현재 본문 확인이 필요하며 정적 검사 통과가 제품 완료·운영 검증을 뜻하지 않는다.
- 검사 실패를 숨기기 위해 예산을 늘리거나 검사에서 파일을 빼지 않는다. 현재 문서는 축약하고 상세 내용은 범위가 분명한 활성 참조 또는 원문 보관으로 이동한다.
- ChatGPT의 실제 사용량·숨은 도구 출력·대화 한도는 이 저장소가 직접 측정하거나 무제한으로 만들 수 없다. 출력은 필요한 증거와 결과만 제한한다.
